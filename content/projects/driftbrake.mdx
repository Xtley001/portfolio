# Driftbrake: Simulation-to-Reality Drift Detection & Halt Guard

**Driftbrake** is a published, production-grade Rust workspace (`cargo add driftbrake`) and compiled Python native extension (`pip install driftbrake-py`) engineered to pre-flight simulate transactions against local chain state, track simulated versus realized on-chain profit upon block confirmation, and halt live trading strategies the moment realized performance drifts from prediction — before phantom drift compounds into real capital loss.

## The Simulation-to-Reality Drift Problem

In high-frequency decentralized finance (MEV extraction, protocol liquidations, and cross-DEX statistical arbitrage), searchers simulate candidate transactions against local state before broadcasting. However, between simulation and block inclusion:
1. **State Mutation & Frontrunning:** Competing searchers or incoming retail flow alter pool reserves, causing slippage or outright reverts.
2. **Hidden Execution Costs:** State-access gas spikes, dynamic base fees, and priority tip surges erode simulated margins.
3. **Model Inaccuracy:** Approximated curve math or stale oracle state generates phantom profits that vanish on-chain.

Without an automated, deterministic halt guard, execution bots continue firing into failing regimes, incurring severe capital bleed through burned priority gas and failed transaction reverts.

## Workspace Architecture (v0.2.0)

Driftbrake is architectured as a modular, trait-driven multi-crate workspace re-exported under a facade crate with zero mandatory REVM or Alloy dependencies in its core:

```
driftbrake/
├── driftbrake/            # Facade crate: re-exports core + reconcile + poller + journal
│   ├── core/              # Chain-agnostic traits, zero REVM/alloy dependencies
│   ├── reconcile/         # Institutional multi-guard halt engine
│   ├── journal/           # Crash-resilient binary Write-Ahead Log (WAL) with CRC32
│   └── receipt-poller/    # Block-time-aware receipt polling & gas accounting
├── driftbrake-py/         # Python native extension (PyO3, ABI3 Stable, pip)
├── revm-backend/          # Opt-in concrete SimEngine (fork-and-simulate with bounded RPC)
├── benchmark/             # Parameter sweep & false-halt / missed-catch calibration CLI
└── examples/
    └── toy-arbitrage/     # End-to-end 2-pool arbitrage strategy against testnet fork
```

## Institutional Multi-Guard Halt Hierarchy

The `driftbrake-reconcile` engine evaluates execution history against an institutional multi-tiered guard policy:

1. **Fast-Trip Guard:** Immediately halts on acute single-event or consecutive severe drift drops below safety thresholds.
2. **Slow-Window Mean Guard:** Accumulates rolling-window moving averages to detect insidious statistical erosion that stays above the fast threshold.
3. **Revert-Burst Guard (`RevertBurstConfig`):** Trips when consecutive on-chain reverts occur within a sliding block window, preventing spam attacks.
4. **Revert Gas Budget Guard (`RevertGasConfig`):** Tracks cumulative gas burned by reverted transactions (`gas_used` × `effective_gas_price`) and halts when the gas budget is exhausted.
5. **Volume-Weighted Average Realization (VWAR: `VolumeWeightedConfig`):** Weights drift ratios by transaction capital magnitude, preventing small winning trades from masking large losing trades.
6. **High-Watermark Net Drawdown Cap (`DrawdownConfig`):** Enforces a hard stop if cumulative net profit drops below peak historical high-watermark drawdown limits.

```rust
use driftbrake::{HaltDecision, ReconcileHistory, ReconcilePolicy};

// Institutional default configuration wiring all 6 guards
let mut policy = ReconcilePolicy::institutional_default();
let mut history = ReconcileHistory::new();

// In execution loop:
match policy.evaluate(&history) {
    HaltDecision::Continue => {
        // Safe to proceed with next bundle/transaction
    }
    HaltDecision::Halt(reason) => {
        // Immediate panic halt to preserve capital
        eprintln!("Strategy execution halted: {reason:?}");
        std::process::exit(1);
    }
}
```

## Crash Resilience: Binary Write-Ahead Log (WAL)

To prevent risk state amnesia during daemon restarts or container evictions, `driftbrake-journal` implements a high-throughput binary Write-Ahead Log:
- **Zero-Copy Serialization:** Bincode-encoded fixed-header append log.
- **Data Integrity:** IEEE 802.3 CRC32 checksums on every log frame.
- **Torn-Write Recovery:** Automatic log truncation on startup if an uncompleted write frame is detected from an abrupt process termination.
- **Process Locks:** Exclusive file locking (`fs2`) preventing multi-instance write collisions.

## Python Native Extension (`driftbrake-py`)

Built with PyO3 targeting the CPython Stable ABI (`abi3`), `driftbrake-py` brings Rust execution speed to Python quant workflows and backtesting harnesses:

```python
from driftbrake import ReconcileHistory, ReconcilePolicy, StrategyHaltedError

policy = ReconcilePolicy(
    fast_window=3,
    fast_threshold=0.50,
    slow_window=20,
    slow_threshold=0.70,
    max_consecutive_reverts=3,
)
history = ReconcileHistory()

# Record pre-flight prediction vs confirmed receipt
history.append(predicted_profit=1_000_000, realized_profit=950_000)

decision = policy.evaluate(history)
if decision.is_halted:
    raise StrategyHaltedError(f"Halted: {decision.reason}")
```

Additionally, `driftbrake-py` exposes `run_sweep_raw()`, enabling quants to backtest thousands of threshold combinations against historical simulation logs in milliseconds via vectorized native loops.
